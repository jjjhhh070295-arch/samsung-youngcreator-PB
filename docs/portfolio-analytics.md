# PB 수동 포트폴리오 분석 V1

## 기존 구조와 연결

- Next.js 14 App Router / React 18 / TypeScript. Python 및 신규 의존성 없음.
- `ManualPortfolioBuilder`가 자산군 배분과 선택 종목을 React state 및 고객별 localStorage에 저장한다. 검색 API와 선택/저장 로직은 유지한다.
- 기존 검색 결과: `symbol`, `name`, `exchange`, `currency`, `kind`, `source`, `price`. 자산군은 투자 노출 분류이며 상장 통화와 다를 수 있다. 국내 상장 미국 ETF는 KRW 그대로 분석한다.
- 자산군 비중과 `weightWithinClass`는 각각 0~100. 분석 경계에서 두 값의 곱 / 10000으로 전체 포트폴리오 비중(0~1)으로 변환한다. 모든 활성 자산군의 내부 비중과 전체 비중이 완성되어야 분석한다.
- 현재 미국 데이터는 Python yfinance가 아니라 Yahoo HTTP API이며 한국 데이터는 Naver HTTP API다. 기존 일봉 함수는 개별종목 분석용 2년·현재가 결합이므로 변경하지 않고 같은 제공처에 분석 전용 기간 조회를 추가했다.
- `PortfolioAnalyticsCards` → `POST /api/portfolio/analytics` → `service` → 제공처 / 순수 계산 모듈. API는 포트폴리오를 저장하거나 종목을 자동 선택하지 않는다.

## 계산 계약

- 기본 5Y / quarterly / KRW. 1Y·3Y·5Y·10Y, none·monthly·quarterly·semiannual·annual 지원. 서비스는 USD 기준통화도 지원한다.
- 초기 NAV 100. 리밸런싱 사이에는 보유 수량을 고정하여 비중이 표류한다. 새 달/분기/반기/연도의 첫 공통 관측일 직전 종가로 목표 비중에 재설정한다. none은 처음 설정한 수량을 끝까지 유지한다.
- CAGR은 실제 시작/종료일의 달력 일수 / 365.25로 연환산한다. MDD와 변동성은 포트폴리오 NAV에서 계산한다. 변동성은 표본 표준편차 × √252. recoveryDays는 고점부터 회복일까지 달력 일수이며 미회복은 null이다.
- 가격은 날짜 정렬·중복 제거·유효성 검증 후 실제 공통 날짜만 사용한다. 휴장과 제공처 누락을 확정할 거래소 캘린더가 없으므로 forward-fill을 하지 않는다. 공통 날짜에서 제외된 관측이 있으면 경고한다. 공통 날짜 간 간격이 2주를 초과하면 MDD/변동성을 숨긴다. 한국·미국의 연휴가 겹치면 10일 이상 관측이 없을 수 있어 2주를 품질 기준으로 사용하며, 휴장일의 확정 판정은 아니다. 관측이 충분하지 않으면 과거 지표는 null이다.
- 거래소별 마감 시각은 동시가 아니다. 날짜 기준 분석이며 공통 날짜 수익률은 여러 거래일을 포함할 수 있다. √252 변동성은 이 경우 근사치다.
- 미국 종목에는 동일 날짜 USD/KRW(`KRW=X`)를 곱한다. USD 기준 분석 시 KRW 종목을 환율로 나눈다. 환율 부재 시 현지통화 과거 수익률을 혼합하지 않고 과거 지표를 null로 반환한다.
- 신규 상장/불완전한 기간은 실제 공통 시작일로 단축하고 경고한다. UI는 실제 날짜 및 단축된 기간을 표시한다.
- Yahoo는 수정종가를 우선하며 일반 종가와 혼합하지 않는다. Naver는 가격 수익률이며 배당 재투자 및 기업행동 조정이 보장되지 않음을 항상 표시한다. 따라서 혼합 포트폴리오는 완전한 총수익률 백테스트가 아니다.

## 기대수익률

- 결과는 비중 가중합과 종목별 value/method/confidence/source/calculationDate/assumptions를 포함한다.
- 개별주식: 3년 EPS·목표 PER 가격 CAGR + 배당. 일부 입력만 있으면 성장률 0%, 현재 forward PER 유지 등의 가정을 공개한다. 분기 이익성장률을 장기 EPS 성장률로 사용하지 않는다.
- Yahoo 공개 응답에서 안정적인 장기 성장 추정치·목표 PER는 확보되지 않아 현재 어댑터는 이를 채우지 않는다. 추가 공급자는 Fundamentals 인터페이스로 연결할 수 있다. 한국 펀더멘털은 현재 어댑터에 없으므로 충분한 이력이 있을 때만 과거 CAGR 대용치를 사용한다.
- 채권/현금성 ETF: YTM − 보수, SEC yield, distribution yield 순. SEC/distribution yield는 펀드 수준 수익률이므로 보수를 이중 차감하지 않는다. 현재 Yahoo summaryDetail.yield는 distribution yield로만 취급한다. YTM/SEC를 추정하여 만들지 않는다.
- 주식형/배당형/원자재 ETF에 개별주식 EPS 모델을 적용하지 않는다. 충분한 이력(최소 1년, 관측 120개)에서는 과거 CAGR 대용치를 사용하며 이력도 부족하면 `insufficient_evidence`, value null을 반환한다. ETF 가격 CAGR에서 보수를 다시 차감하지 않는다.
- 임시 자산군 수익률은 사용하지 않는다. 근거 부족 종목의 기대수익률·기여도 및 전체 기대수익률은 null이며, 추정 가능한 비중만 `expectedReturnCoverage`(0~1)로 반환한다. 해당 종목을 제외하거나 비중을 재조정하여 전체 수익률처럼 제시하지 않는다. 대기 현금은 기존의 미투자 예수금(이자 0%) 처리다.
- 근거 부족 종목이 있으면 종목명·비중·부족 사유와 전체 산출 보류를 native dialog로 알린다. 동일 대상/사유의 단순 비중 변경은 팝업을 반복하지 않으며 재확인 버튼을 제공한다. 새 대상/사유가 생기면 다시 알린다. 문제 해결 시 경고를 제거한다. 과거 지표 계산은 독립적으로 유지한다.
- 외화 펀더멘털 및 자산군 기대수익률은 미래 FX 변화 0% 가정. 과거 CAGR 대용치는 FX 데이터가 있으면 기준통화 가격에서 계산한다.
- 세금, 거래비용, 최적화 및 미래 환율 예측은 포함하지 않는다.

## 데이터 및 오류 처리

- 경고 팝업에서 PB가 근거 부족 종목별 연 기대수익률(-100%~1000%)과 근거(필수, 500자 이하)를 입력하면 `pbScenario` 순수 함수가 별도 시나리오를 계산한다. 자동 기본값은 없으며 0%와 음수도 명시적 입력이어야 한다.
- 별도 결과는 현재 비중 × (기존 추정치 또는 근거 부족 종목의 PB 입력값)의 합이다. 입력되지 않은 종목이 남으면 전체 시나리오도 보류한다. 기존 분석 결과, NAV, 과거 지표는 변경하지 않는다. 입력한 기준통화 수익률, 근거, 입력일 및 PB 직접 입력 출처를 보여준다.
- PB 가정은 컴포넌트 상태로만 유지한다. 비중/기간 변경 시 현재 결과에 재적용하며, 더 이상 근거 부족이 아닌 종목 및 제거된 종목에는 적용하지 않는다. 고객 변경·새로고침·화면 이탈 시 초기화되고 DB/저장 포트폴리오에는 반영하지 않는다. 해제 버튼으로 제거할 수 있다.

- 클라이언트 요청 500ms debounce, 오래된 요청 abort 및 결과 키 비교로 이전 구성 결과가 새 구성에 표시되지 않도록 한다.
- 서버는 종목·통화·유형·기간별 15분 TTL 메모리 캐시(최대 200 항목), 진행 중 요청 공유, 제공처 12초 timeout 및 종목 최대 6개 병렬 조회. 실패한 캐시는 제거한다. 서버리스 인스턴스 간에는 캐시가 공유되지 않는다.
- 입력 최대 60종목, 30KB 및 허용된 값/비중 검증. 지원하지 않는 통화는 UI에서 명시적으로 차단한다.
- 일부 종목 조회 실패 시 해당 종목을 몰래 제외하거나 비중을 재분배하지 않는다. 기대수익률은 근거 부족으로 산출 보류하고 과거 포트폴리오 지표도 미제공한다.

## 검증

`npm test`에 포트폴리오 테스트 포함. 사용자 요청 9개 사례 외에 리밸런싱 표류, 회복 기간, FX 역변환, 장기 공백, 제공처 파싱, 펀더멘털 fallback, 국내 상장 해외 ETF 통화 및 서비스 실패를 검증한다.

타입: `npx tsc --noEmit --incremental false`. 린트: `npm run lint`.
